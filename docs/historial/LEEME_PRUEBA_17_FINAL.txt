CAMBIOS FINALES INTEGRADOS
--------------------------
1) SEGUIMIENTO MANUAL
   - El navegador lee el .xlsx localmente con JSZip.
   - El archivo Excel completo NO se almacena en Supabase.
   - Se envían únicamente las filas normalizadas necesarias.
   - Regla obligatoria:
       Viaje = F          -> SEGUIMIENTO_HISTORICO
       Viaje != F         -> SEGUIMIENTO_DIARIO
     Esto incluye IDA, RETORNO, PARADA y cualquier otro valor no F como ABIERTOS.
   - Si una OC ya existe, se actualiza y, si corresponde, se mueve de DIARIO a HISTORICO o viceversa.
   - Se eliminan duplicados de la misma OC dentro de seguimiento_staging durante la sincronización.
   - Se registra auditoría de cambio de ORIGEN y un resumen de cada importación.
   - Se limpian borradores web y el control de reporte después de importar, obligando a una nueva revisión consistente.

2) PANEL ADMINISTRACIÓN
   - Solo visible para rol ADMIN con acceso a CEMENTO.
   - Muestra:
       Base de datos global / 500 MB
       Egress pesado registrado por la app en el mes / 5 GB
       Storage actual / 1 GB
   - Muestra estimación por itinerario para CEMENTO, CERRO VERDE y QUELLAVECO.
   - El tamaño por itinerario es aproximado a nivel de filas y no incluye índices/WAL/overhead.
   - Egress por itinerario empieza a contabilizarse desde PRUEBA 17 y registra el tráfico pesado controlado por la app: descargas Excel y respuestas GPS/CLocator.
   - El panel Usage de Supabase continúa siendo el dato oficial de facturación/consumo total.

3) ARCHIVOS Y EGRESS
   - ARCHIVOS solo consulta conteos livianos al abrirse.
   - SEGUIMIENTO_DIARIO.xlsx y SEGUIMIENTO_HISTORICO.xlsx se generan y transfieren recién al presionar DESCARGAR EXCEL.
   - No existe descarga automática de los Excel por entrar a la pantalla.
   - Las descargas se registran en app_egress_log. Las respuestas GPS/CLocator también se registran porque el tráfico de Edge Functions forma parte del egress real de Supabase.

4) SEGURIDAD
   - El nuevo endpoint cemento-admin exige Firebase válido + usuario activo + rol ADMIN + itinerario CEMENTO.
   - SERVICE_ROLE permanece exclusivamente dentro de Edge Functions.
   - Las tablas administrativas tienen RLS habilitado y sin permisos para anon/authenticated.
   - Los RPC nuevos solo se conceden a service_role.

DESPLIEGUE
----------
A) Ejecutar primero la migración SQL de PRUEBA 17 en Supabase.

B) Desplegar funciones (Firebase token validado dentro de cada Edge Function):
   npx supabase@latest functions deploy cemento-admin --project-ref otvdwqbrqvxahyzfkhds --no-verify-jwt
   npx supabase@latest functions deploy cemento-consulta --project-ref otvdwqbrqvxahyzfkhds --no-verify-jwt
   npx supabase@latest functions deploy cemento-reporte --project-ref otvdwqbrqvxahyzfkhds --no-verify-jwt
   npx supabase@latest functions deploy cemento-clocator --project-ref otvdwqbrqvxahyzfkhds --no-verify-jwt

C) Publicar Firebase Hosting:

VERIFICACIÓN OPERATIVA
----------------------
1. Iniciar sesión con cuenta ADMIN.
2. Confirmar que aparece ADMINISTRACIÓN.
3. Abrir ADMINISTRACIÓN y comprobar las tres cuotas.
4. Seleccionar SEGUIMIENTO MANUAL.xlsx.
5. Verificar el resumen de abiertas/cerradas antes de aplicar.
6. Aplicar y confirmar:
     SELECT origen, count(*)
     FROM seguimiento_staging
     WHERE itinerario='CEMENTO'
     GROUP BY origen;
7. Confirmar que una OC Viaje=F está en HISTORICO y una IDA/RETORNO/PARADA está en DIARIO.
8. Abrir ARCHIVOS: la pantalla solo debe mostrar conteos.
9. Pulsar DESCARGAR EXCEL: recién allí se genera la descarga y aumenta app_egress_log.
10. Volver a ADMINISTRACIÓN y confirmar el incremento del Egress APP.
